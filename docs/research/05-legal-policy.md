## 1. 얼굴·번호판 자동 블러

### 법적 근거
- **개인정보 보호법 제25조의2** [확인]: 2023-09-15 시행. **업무 목적**으로 이동형 기기를 운영하는 자는 공개된 장소에서 개인 영상을 촬영할 수 없다. 예외는 동의·정당한 이익, 또는 촬영 사실을 명확히 표시했고 거부 의사가 없는 경우 등이다. 목욕실·화장실·탈의실은 누구도 촬영할 수 없다.
- 시행령상 **스마트폰·디지털카메라도 이동형 기기에 포함**된다 [2차].
- PIPC 안내서(2024-10) [2차]: 촬영 사실만으로는 부당한 침해라 보기 어렵다. 가급적 익명·가명 처리할 것. 거부 의사를 밝히면 중단·삭제할 것.
- **누가 대상인가 [미확인, 핵심 쟁점]**: 개인이 사적으로 촬영하는 것은 대상이 아니라는 해석이 일반적이다. 그러나 **회사가 촬영 대상을 지정하고 보상하면 "업무 목적"으로 평가될 위험**이 있다. 업로드를 받는 순간 회사는 개인정보처리자가 된다(제15조, 제29조 적용).
- **가명처리(제28조의2)**는 통계·연구·공익기록 목적에만 허용된다. **상업 게임 게시물은 익명화(재식별 불가)가 목표**다.
- **번호판** [2차]: PIPC 2024 안내서는 "일반적으로 개인정보 아님"으로 해석했다. 다만 해석이 바뀌어 왔고 비판도 있다. 카카오·네이버는 번호판을 블러한다. → **법적 의무 여부와 무관하게 일괄 블러한다.**
- **초상권** [확인]: 2004다16280, 2020다227455(이익형량). 상업 게임에 식별 가능한 얼굴이 영구 3D 에셋으로 남으면 이익형량에서 불리하다.

### 3D 파이프라인 설계
splat의 색은 **모든 입력 프레임에서 역투영**돼 만들어진다. 따라서 프레임 하나만 놓쳐도 얼굴이 3D에 남는다. 처리 순서는 다음과 같다.

1. 업로드
2. **얼굴·번호판 검출 → 블러** (EgoBlur)
3. **사람은 세그멘테이션 → 학습에서 제외**(loss mask). 블러하면 유령 같은 흔적이 남는다.
4. 블러된 프레임만으로 재구성
5. **재구성 결과를 여러 시점에서 렌더링해 재검출**(QA)
6. 원본은 **암호화 단기 보관 후 파기**하고 감사 로그를 남긴다.
7. 게시 후 **신고 → 수정** 루프를 운영한다(검출 누락은 불가피하다).

추가로 창문 너머 실내, 모니터 화면, 우편물 같은 텍스트 개인정보도 검수 체크리스트에 넣는다.

## 2. 사유지·건물 내부: 소유자 동의 구조

### 법적 쟁점
- **건조물침입** [확인]: 대법원 2017도18272 전원합의체. 일반인 출입이 허용된 곳에 통상적 방법으로 들어가면 원칙적으로 침입이 아니다. 그러나 출입금지 구역이나 퇴거 요구 불응은 별개다. 업무방해 등 민사 리스크도 있다 [미확인].
- **건축저작물** [확인]: 저작권법 제35조 제2항은 개방된 장소에 항시 전시된 저작물의 복제를 허용한다. 다만 ① 건축물을 건축물로 복제하는 경우와 ④ **판매 목적의 복제**는 제외된다. 유료 게임이나 인게임 판매에 ④가 적용되는지는 판례가 없다 [미확인].
- **골프장 판례** [확인]:
  - 2016다276467: 실제 장소의 종합 이미지를 3D로 재현해 상업적으로 쓴 것을 **부정경쟁방지법 성과도용**으로 인정했다.
  - 2024다229671·228661(2026-02-26): **소유주와 협약을 맺었더라도 설계자 저작권 침해가 성립할 여지**가 있다.
  - → **소유자 동의 ≠ 건축가·인테리어 디자이너 저작권 해결**이다.
- **상표·간판** [미확인, 분석]: 배경에 우연히 찍힌 간판은 "상표로서의 사용"이 아닐 가능성이 높다. 그러나 게임 내 상점·아이템·마케팅에 쓰면 리스크가 크다.

### 설계안: 권리관리 흐름

```
[실외·공도]  자동 가림 → 게시 → 주소 단위 옵트아웃 레지스트리 → 신고 시 즉시 비공개
[실내·사유지] 소유/관리 권한 인증(사업자등록·등기·임대차) → 전자 동의서
             (촬영·3D화·게임 게시·수정·철회 범위 + 건축/인테리어 저작권 보증·면책)
             → 촬영 → 파이프라인 → 소유자 미리보기 승인 → 게시 → 언제든 철회 가능
[공통]       랜드마크·유명 건축물·상업시설 블랙리스트(라이선스 대상)
             3D 에셋 판매·다운로드·추출 기능 없음
             마케팅 이미지에서 실제 상호 배제
```

- 동의 기록(`consent.record_id`)은 Zone manifest에 연결된다(ARCHITECTURE.md 3.2). 철회되면 Index에서 즉시 내린다.
- **MVP**: 실내 1곳은 **내가 직접 소유자와 서면 동의**를 받는다. 1쪽짜리 동의서 템플릿은 Phase 1에서 초안을 만들고, 변호사 검토를 권장한다.

## 3. 한국 공간정보 규제 대응

### 3.1 국가공간정보 기본법 제35조의6 (신설, 2026-12-03 시행) [확인]
- "공간정보를 생산·관리·가공·유통하려는 자"는 다음 시설을 **위장·삭제·흐림 등으로 보안처리**해야 한다.
  - 국방부가 통보한 군사시설
  - 국정원이 통보한 국가중요시설
- 국토부는 요청이 있으면 **보안성 검토**를 하고 보안 DB를 구축한다. 보안처리를 하지 않으면 **시정명령** 대상이다.
- **민간이 자체 구축한 공간정보가 입법 취지에 명시**돼 있다. → 크라우드 3D 재구성도 적용될 가능성이 높다 [분석].
- 시행령 세부 내용은 [미확인].

### 3.2 군사기지법 / 국가중요시설 / 드론
- 군사기지 및 군사시설 보호법 제9조 [2차]: 보호구역 안 군사시설의 **촬영·묘사·측량**을 금지한다. 형사처벌 대상이다.
- 드론 [2차]:
  - 서울 대부분은 비행금지·제한구역이다(P-73, 관제권). 비행 승인이 필요하다.
  - 국방부의 사전 항공촬영 허가는 2022-12에 폐지됐지만, 촬영금지시설 제한은 유지된다.
  - → **드론 촬영물은 받지 않는다**(초기).

### 3.3 공간정보관리법 제16조 (기본측량성과 국외반출) [확인]
- 대상은 **국토지리정보원의 기본측량성과**(지도, 측량용 사진)다. 자체 촬영 데이터에는 원칙적으로 해당하지 않는다고 본다 [분석].
- 다만 베이스맵에 쓰는 **NGII DEM·정사영상 등 원천 데이터를 해외 서버에 두는 것**은 확인이 필요하다 [미확인].
- 2026-02-27 구글 지도 조건부 반출 허가의 조건이 **민간 3D 서비스의 사실상 기준선**이다 [2차]. 조건은 보안시설 가림, 국내 서버 가공, 정부 검토, 레드버튼이었다.

### 3.4 대응 방안 (파이프라인 반영)
1. **보안구역 지오펜스 레이어**(ARCHITECTURE ③ 단계)
   - 군사시설, 국가중요시설, 정부청사, 용산 대통령실·국방부 일대 등을 넣는다.
   - 공식 목록은 비공개이므로 **보수적으로 자체 목록을 만들고 넓은 버퍼**를 둔다. 제35조의6에 따른 보안 DB 제공 절차가 생기면 교체한다.
2. 해당 구역 업로드는 **차단**한다. 경계 근처는 **사람 검수 + 가림**을 거친다.
3. **파일럿 지역은 보안시설과 떨어진 일반 주거·상업 골목**으로 고른다.
4. 호스팅은 **국내 리전 우선**으로 한다. 원천 공공데이터는 국내에만 둔다.
5. 2026-12 시행 전후로 **국토지리정보원에 보안성 검토 절차를 질의**한다. 공개 서비스 이전에 한다.

1. 크라우드 촬영이 제25조의2의 **"업무 목적"**에 해당하는지, 그리고 적법한 근거를 어떻게 설계할지

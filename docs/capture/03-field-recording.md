# WP-17 현장 녹음 절차

상태: 문서 완료·설계/현장 검증 대기(2026-09-28). 현장 녹음·음질 판정·새 음원 채택은 미실행이다. 수치와 장비 선택은 Fable 검토 전 가설이다.

## 장비와 사전 점검

이미 보유한 아이폰 내장 마이크로 먼저 30초 시험 녹음한다. 폰을 손으로 움직이지 않고 고정해 취급 잡음을 줄인다. 바람 소리·대화·클리핑이 들리면 본 녹음을 시작하지 않는다. 앱/OS 버전, 실제 파일 채널·샘플레이트, 자동 처리 설정을 기록한다. 아이폰에서 나온 파일을 곧바로 PCM WAV라고 가정하지 않는다.

[확인] Apple 설명서는 내장 마이크·호환 외장 마이크 녹음을 안내한다. iCloud에 음성 메모를 켜면 같은 계정 기기에 동기화되므로, 원본의 외부 전송을 막는 프로젝트 운영 설정을 녹음 전에 확인한다. 기기에서 실제로 확인한 설정만 기록한다. [Apple Voice Memos](https://support.apple.com/guide/iphone/make-a-recording-iph4d2a39a3b/ios), 확인일 2026-09-28.

외장 마이크와 바람막이는 내장 시험에서 바람/취급 잡음이 실패한 경우 비교할 후보다. 호환 연결·입력 인식·고정·모니터링을 먼저 확인한다. 아직 모델이나 구매를 선택하지 않는다. 같은 위치에서 내장/외장 각30초를 받아 소유자 청취로 차이를 평가한다.

## 현장 계획 — 가설

| 대상 | 위치/시간 | 분량 | 현장 합격 확인 |
|---|---|---|---|
| 도시 원경 낮 | Zone별 고정점, 낮 현장 방문 | 3분×3테이크 | 바람/대화/음악/취급 잡음 없는 구간 |
| 도시 원경 밤 | 같은 고정점, 야간 안전·출입 조건 충족 시 | 3분×3테이크 | 낮과 같은 방향/높이 기록 |
| 실내 룸톤 | 출입·녹음 허용 공간, 사람 대화 없는 때 | 2분×3테이크 | 기기/설비 소음 구분 |
| 발소리 | 허용된 아스팔트·타일·계단, 본인 발소리 | 걷기/달리기 각20보×3 | 겹친 대화/타인 발소리 없음 |
| 착지 | 안전한 평지, 본인 가벼운 착지 | 10회 | 과도한 동작/위험한 장소 제외 |

각 테이크 앞뒤10초는 손대지 않고 기다린다. 사람이 접근하거나 대화/방송/음악이 섞이면 중단하고 해당 구간은 배포 후보에서 제외한다. 음성 익명화나 AI 분리로 사용 가능하다고 판정하지 않는다. 원본은 로컬 비공개 보관, 저장소/외부 AI로 보내지 않는다.

통신비밀보호법 원문과 적용 범위는 **[확인 필요]**다. 위 대화 제외 규칙은 프로젝트 운영 규칙이며 법적 적법성 판정이 아니다. 실제 촬영·녹음 전 공개 전 자문 항목과 권한을 확인한다.

## 파일·후처리 — 가설

원본 이름: `<zone_id>_<YYYYMMDD>_<HHMMSS>_<day|night|interior|footstep>_<take>.원래확장자`. 실명·상호를 이름에 넣지 않는다. 원본은 수정하지 않고 파생 WAV에 편집 번호 `_edit01`을 붙인다. 별도 로컬 기록에 장치·마이크·방향·높이·날씨·시간대·녹음자·허용 근거·제외 구간을 남긴다.

1. 전체 구간을 사람이 청취해 대화·음악·사적 내용·클리핑을 제외한다. 명료한 대화 구간을 골라 전사하지 않는다.
2. 파생본에서 필요 구간을 선택하고 DC offset·피크를 점검한다. 정규화 초기 후보는 −6dBFS peak이며 최종 음량 기준은 아니다. stereo 두 채널의 상대 밸런스를 유지한다.
3. [확인] Audacity Normalize는 DC offset 제거와 peak 조정 기능을 제공하며 채널별 독립 정규화 옵션이 있다. 여기서는 독립 옵션을 끄는 방식으로 비교한다. [Normalize 매뉴얼](https://manual.audacityteam.org/man/normalize.html), 확인일 2026-09-28. 도구 설치·프로젝트 파이프라인 채택은 아직 수행하지 않았다.
4. 루프 시작/끝에서 급격한 이벤트를 피하고 짧은 크로스페이드로 접합한 뒤 헤드폰으로10회 반복 청취한다. 루프 길이/페이드 길이와 편집 내역을 기록한다. 간격이 들리면 다른 구간을 고른다.
5. WP-13 임포터용 파생본은 PCM16/48kHz, ambience mono 또는 stereo·발소리 mono, 항목5MB/총40MB 예산에 맞춘다. 48kHz PCM16 stereo는 초당192,000바이트이므로 긴 원본을 그대로 반입하지 않는다. 루프20초는 약3.84MB+헤더다.
6. 저자·출처·사용 근거·확인일·편집 내역을 검토해 채택된 파일만 audio.json과 ATTRIBUTION/크레딧으로 잇는다. 실제 현장 원본에 `project-generated`를 쓰지 않는다. 현행 허용 라이선스/자체 녹음의 권리 표현이 맞지 않으면 계약 확장을 먼저 제안한다.

## 현장 기록과 인계

시간은 KST로 기록한다. 낮은 10~16시, 밤은 20~22시를 초기 방문 후보로 하되 통행·안전·사용 허용 조건을 우선한다(품질 가설). Zone마다 대표 야외 고정점1개를 정하고 낮/밤에 재방문한다. 지도에는 공개 상호 대신 내부 point ID를 쓴다. 위치가 달라지면 새 point ID로 분리한다. 마이크 높이 초기 후보는1.5m, 발소리 수음은 바닥에서0.5m로 비교한다. 실제 값과 수음 방향을 기록한다.

바람막이는 마이크에 맞는 크기로 장착하고 캡슐을 손으로 가리지 않는다. 바람막이를 사용해도 저주파 돌풍이 남으면 위치/시간을 바꿔 다시 녹음한다. 후처리로 복구될 것이라 가정하지 않는다. 실내 녹음은 별도 허용을 확인하고 소유자의 대화도 환경음 후보에는 넣지 않는다.

루프 후보는10~20초, 접합 크로스페이드는0.1~0.5초로 시작한다(가설). 같은 배경 구간끼리 겹쳐 믹스해 별도 파일로 만든 뒤 루프10회 반복을 확인한다. 단순 앞뒤 fade-in/out은 매 주기 음량 구멍을 만들 수 있어 접합 완료로 간주하지 않는다. 클릭·주기적 차량/발소리·스테레오 위치 점프가 들리면 재편집하거나 다른 구간을 택한다. 원샷은 앞뒤 짧은 여유를 남겨 attack/tail을 자르지 않는다. 재샘플링과 PCM16 변환은 최종 내보내기에 한 번만 적용하고 결과의 실제 헤더를 검증한다.

| 기록 필드 | 채울 값 |
|---|---|
| 세션/Zone/point | 내부 ID·KST 날짜/시간·날씨·방향/높이 |
| 장치 | 폰/마이크/앱·OS·바람막이·입력 설정 |
| 원본 | 로컬 비공개 경로·파일명·SHA256·길이·채널/포맷 |
| 현장 허용 | 녹음자·허용 근거의 비공개 기록 ID·확인일 |
| 청취 검수 | 담당·날짜·대화/음악/클리핑/바람 제외 구간 |
| 파생본 | 원본 구간 초·편집/루프/정규화·최종 peak·PCM 포맷·바이트 수 |
| 권리/표기 | 저자·출처·확인일·변경 내역·채택 판단 |
| 게임 비교 | audio asset ID·gain/master·청취 장치·V-10 결과 |

원본 SHA256은 로컬 `Get-FileHash -Algorithm SHA256 <원본 경로>`로 기록한다. 공개 문서에는 원본 위치·개인 허용서·타인 이름을 복사하지 않는다. 표기와 재현에 필요한 최소 메타데이터만 권리 검토 뒤 공개한다.

완료 기준: 운영 기록이 채워지고, 대화/음악 없는 파생본을 사람이 전량 청취했으며, 포맷/예산·루프10회·출처/확인일·권리 표현이 확인돼야 반입 후보가 된다. 그 뒤 JSON+임포트 및 V-10의 실제 재생/소유자 밸런스를 통과해야 채택한다. 지금 완료된 것은 이 절차 문서이며 녹음·권리 채택·청취는 미실행이다. Zone 위치 점은 [WP-17 변경 제안](../plan/WP-17-field-recording.md)을 먼저 검토한다.

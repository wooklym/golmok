## D-013 포토 모드

**플레이어 가치**: 실제로 걸었던 골목을 원하는 시간대·구도로 찍어 남긴다. 실사 재구성 게임의 가장 자연스러운 공유 동력이고, DEVELOPMENT-PLAN §1.2 플레이어 경험 5에 이미 "(선택)"으로 들어가 있다. 개발 측면에서도 스파이크·회귀 비교용 캡처 도구와 겹친다.

**범위 제안**
- 최소판(M7): 키 하나로 진입 → 게임 일시정지(캐릭터·NPC 정지) → 자유 카메라(캐릭터 반경 제한, 벽 충돌) → FOV·노출 보정·피사계 심도(초점 거리·조리개) → HUD 숨김·캐릭터 숨김 토글 → 촬영(고해상도) → `Saved/Screenshots/Golmok/`에 PNG + 메타 JSON(위치·zone_id·프리셋·시각).
- 확장(Phase 2): 시간대 슬라이더(D-015 연동), 필터(LUT 몇 개), 캐릭터 포즈, 비율 가이드, 사진첩(D-017 연동).

**구현 규모**
- C++: `Photo/GolmokPhotoMode`(PlayerController 확장 또는 서브시스템) — 자유 카메라 폰, PostProcess 오버라이드(DOF·노출), 촬영은 WP-05 `golmok.screenshot`이 쓰는 `HighResShot` 경로 재사용. 1 WP(Fable ultracode, 게임성 직접 영향 → DEVELOPMENT-PLAN §7.4).
- UI: 최소 위젯(UMG) — Blueprint 최소 원칙(D-003) 때문에 레이아웃만 위젯 에셋, 로직은 C++.
- Python: 없음(필요 시 캡처 메타 → 컨택트 시트는 `spike_runner` 재사용).
- 에셋: LUT 몇 장(엔진 기본 또는 자체 제작).
- 공식 근거: "The high resolution screenshot console command is a great cross-platform tool for taking very high resolution screenshots" [확인: https://dev.epicgames.com/documentation/en-us/unreal-engine/taking-screenshots-in-unreal-engine].

**의존**: WP-05 디버그 스크린샷(🟢 V-03, 단 "`golmok.screenshot`에 HUD 포함" 발견 → 포토 모드는 HUD를 끄고 찍어야 함), D-010(splat 경로면 DOF·반사 품질이 메시와 다를 수 있음), 입력 매핑(C++ Enhanced Input 추가).

**리스크**
- 법·정책: 사진에 실제 간판·상호·(블러 누락된) 얼굴이 담겨 **외부로 공유**된다. 블러 재검사(ROADMAP 1.6)와 05 문서의 공개 전 자문 항목(초상권·상표·저작권)에 "사용자 촬영 스크린샷 공유"를 추가해야 한다 [확인 필요 — 법률 판단은 D-009 공개 전 자문].
- 품질: 자유 카메라가 재구성 범위 밖(구멍·뒷면)을 보면 품질이 무너진다 → 캐릭터 반경 제한 + zone footprint 안으로 제한.
- 성능: 고해상도 촬영 시 VRAM(RTX 5060 8 GB) — 배율 상한.

## D-014 Zone 지도·이동

**플레이어 가치**: "가는 곳마다 찍어 올리는" Zone 누적(D-008)이 게임 안에서 보이게 된다. 서울 지도 위에 내가 올린 골목들이 점으로 쌓이고, 골라서 이동한다. Zone이 늘수록 가치가 커지는 기능.

**범위 제안**
- 지도 화면: 베이스맵 정사영상(D-012 파생물, 이미 게임 안 지형 텍스처로 사용 중)을 축소한 2D 지도 + Zone footprint·이름·촬영일·방문 여부. 현재 위치 표시(게임 안 좌표 → ENU → 경위도, WP-04 Geo).
- 이동: Zone 선택 → 페이드 → 대상 Zone의 스폰 지점으로 텔레포트(해당 셀을 선로드한 뒤). 베이스맵 범위 밖 Zone은 "다른 지역"으로 레벨 전환(여러 베이스맵 레벨이 생길 때).
- 미니맵(선택): 화면 구석 작은 지도. 골목에서는 시야를 가릴 수 있어 기본 끔 제안.

**구현 규모**
- C++: `Map/`(지도 데이터: Zone Index + manifest footprint → 2D 좌표), 텔레포트(`UGolmokZoneSubsystem`에 "대상 zone 선로드 후 이동" API — WP-09의 `LoadAsync`·포털 선로드 패턴 재사용). 1~2 WP.
- Python/도구: 지도 텍스처 생성(`golmok-basemap`에 축소 정사영상 + 도로 레이어 출력 옵션) — 도구 1 WP 또는 기존 WP에 포함.
- UI: 지도 위젯(UMG) 레이아웃 에셋.
- Zone 스키마: manifest에 스폰 지점(`spawn`)·표시 이름이 없으면 추가 필요 → `spec/zone-manifest.md` 변경(WP-02 스키마 버전 관리).

**의존**: WP-09 Zone Index 발견·비동기 로드(🟡, V-07 대기), D-008 홈 Zone 확정, D-012 베이스맵, Zone이 2곳 이상.

**리스크**
- 데이터 정책: 지도에 NGII 정사영상 파생물을 쓰는 것은 D-012에서 저장소 반영이 허용됐지만(사용자 법률 자문) **공개 배포 시 조건**은 별도 확인 [확인 필요, D-009].
- 정책: 게임이 플레이어의 **실제 위치**를 수집하지 않으면 위치기반서비스 신고(05 문서 Phase 3 항목) 대상인지 여부가 달라질 수 있다 — 추측하지 않고 공개 전 자문 항목에 추가 [확인 필요].
- 기술: 텔레포트 직후 대상 Zone 로드 히치(WP-09 §6 히치 표 결과에 따름).

## D-015 시간대·날씨

**플레이어 가치**: DEVELOPMENT-PLAN §1.2 플레이어 경험 3("같은 골목이 다르게 보인다"). 시간대는 이미 MVP에 있고(WP-05, 4 프리셋 + 실내 오버레이), 이 제안은 **시간대 폴리시**와 **날씨 추가**를 나눠 결정하자는 것이다.

**범위 제안**
- (a) 시간대 폴리시(M7): night 프리셋 look-dev([`lighting-night-lookdev.md`](lighting-night-lookdev.md)), 프리셋 사이 연속 시간(슬라이더 또는 실시간 경과) 여부, 가로등·간판 발광(Zone 에셋)의 시간대 연동.
- (b) 날씨(Phase 2): 흐림/맑음은 프리셋(안개·스카이·태양 강도)으로 이미 표현 가능. **비**는 Niagara 빗줄기 + 젖은 표면(러프니스·웅덩이 머티리얼 레이어) + 소리(D-016) + 조명 변화. 눈은 제외 제안(촬영 텍스처가 계절과 안 맞음).

**구현 규모**
- (a) C++ 소(프리셋 키 추가 시 JSON 스키마·`GolmokTimeOfDay`·`lighting.py`·테스트 함께 변경 — WP-05 규칙), 에셋: 가로등 발광은 Zone 제작 쪽.
- (b) 대: C++ `Weather/`(상태·전환), 머티리얼 함수(젖음 레이어 — D-010 결과에 따라 메시 머티리얼 전부에 적용), Niagara 에셋, 사운드. 2~3 WP + look-dev PC 작업.

**의존**: **D-010**(메시면 머티리얼 레이어로 젖음 표현 가능, splat이면 표면 재질을 바꿀 수 없어 비 표현이 매우 제한적 [미확인 — 스파이크에서 확인]), night look-dev, R5(촬영 텍스처에 구운 조명: 흐린 날 촬영이라 맑은 날·밤 조명과 텍스처 음영이 어긋날 수 있음).

**리스크**
- 품질: 흐린 날 찍은 텍스처 위에 강한 태양·밤 조명을 올리면 부자연스럽다(R5). 날씨는 D-010 뒤 스파이크 스크린샷을 보고 판단.
- 성능: 볼류메트릭 안개·빗줄기·젖은 반사(Lumen 반사)가 RTX 5060 1080p 30 fps 하한에 부담 [미확인].
- 참고(5.8): "Lumen Lite is a new medium-quality setting for Global Illumination … It's twice as fast as Lumen high quality"(Beta) [확인: 5.8 릴리스 노트] — 저사양 옵션 후보, 채택은 별도 결정.

## D-016 환경음

**플레이어 가치**: 골목의 소리(멀리 차 소리, 에어컨 실외기, 새, 가게 문 종, 발소리의 바닥 재질 차이)는 시각 품질만큼 "실제 장소"라는 느낌을 준다. 현재 게임에는 소리가 전혀 없다(코드에 오디오 없음).

**범위 제안**
- (a) 기본(M5~M7): 전역 앰비언스 1~2종(도시 원경), 발소리(재질 2~3종: 아스팔트·타일·계단), 실내 진입 시 앰비언스 전환(포털 오버레이와 연동), 시간대별 앰비언스(낮/밤).
- (b) Zone별(Phase 2): Zone 촬영 때 **같은 장소의 소리를 녹음**해 zone 에셋으로 넣는다(`capture/` 가이드에 녹음 절차 추가). 소리 위치(실외기·가게)는 manifest에 점으로.

**구현 규모**
- C++: 발소리(애니메이션 노티파이 또는 이동 거리 기반 + 물리 머티리얼), 앰비언스 관리(Zone·실내·시간대에 따라 크로스페이드) — 1 WP. 엔진 오디오는 MetaSounds 사용: "MetaSound is a high-performance audio system that provides audio designers complete control over a Digital Signal Processing (DSP) graph for generating sound sources" [확인: https://dev.epicgames.com/documentation/en-us/unreal-engine/metasounds-the-next-generation-sound-sources-in-unreal-engine].
- 에셋: 라이선스가 확인된 사운드 라이브러리(무료 CC0 또는 유료 — **구매는 사용자 승인**) 또는 자체 녹음.
- 도구: 녹음 파일 정리(음량 정규화·루프 포인트) — 필요하면 Python 도구.
- 촬영 가이드: 녹음 장비(아이폰 내장 마이크 vs 외장), 바람막이, 1곳당 녹음 시간.

**의존**: 애니메이션 채택안(발소리 노티파이 위치, [`research/09`](../research/09-animation-ue58.md)), 촬영 일정(C-02에 녹음 추가 시), D-002(사운드 라이브러리 라이선스 원문 기록).

**리스크**
- **법률**: 공공장소 녹음에 **다른 사람의 대화**가 담기면 통신비밀보호법(타인 간 대화 녹음 금지 조항)·개인정보(목소리) 문제가 생길 수 있다고 알려져 있으나 이 세션은 법령 원문을 열지 못했다(law.go.kr 본문 로드 실패) → **[확인 필요]**. 권장 운영: 대화가 들리는 구간은 쓰지 않는다(녹음 뒤 사람이 들어서 잘라냄), 필요하면 공개 전 자문(D-009) 항목에 추가.
- 품질: 라이브러리 소리는 "서울 골목"과 안 맞을 수 있다(해외 도시 소리) → (b) 현장 녹음이 품질 최우선 원칙에 맞음.
- 라이선스: 무료 사운드 사이트는 항목마다 조건이 다름(CC-BY 표기 의무, 비상업) → D-002 절차로 항목별 원문 기록.

## D-017 세이브

**플레이어 가치**: 다시 켰을 때 마지막 골목·위치·시간대에서 이어 한다. Zone 지도(D-014)의 방문 기록과 포토 모드(D-013) 사진첩이 여기에 저장된다. Zone이 하나인 MVP에서는 가치가 작다(§1.3 "안 들어감").

**범위 제안**
- 자동 저장(종료·Zone 이동·포토 촬영 시)만, 슬롯 1개. 수동 슬롯 없음.
- 저장 내용: 위치는 **경위도·높이 + zone_id·zone 버전**(UE 좌표를 저장하지 않음 — 베이스맵 원점이나 zone 정합이 바뀌어도 복원), 바라보는 방향, 시간대 프리셋, 방문한 zone 목록, 사진 목록(파일 경로만), 설정(감도 등, 설정 UI가 생긴 뒤).
- 복원 규칙: zone이 새 버전으로 바뀌었거나 없어졌으면 그 zone의 스폰 지점(D-014 manifest `spawn`)으로, 그것도 없으면 홈 Zone.

**구현 규모**
- C++: `USaveGame` 서브클래스 + 저장/불러오기 서브시스템, 비동기 저장. 공식 문서: "AsyncSaveGameToSlot is the recommended method for saving the game. Running asynchronously prevents a sudden framerate hitch" [확인: https://dev.epicgames.com/documentation/en-us/unreal-engine/saving-and-loading-your-game-in-unreal-engine]. 1 WP(Opus 가능 — 게임 감각 영향 작음).
- 테스트: 좌표 변환은 WP-04 Geo 순수 헤더로 g++ 교차검증, UE 자동화 1~2개.

**의존**: D-014(스폰 지점, 방문 기록), WP-04 Geo 변환, zone manifest 버전 규약(WP-02).

**리스크**
- 호환성: 세이브 형식 버전 필드 필수(나중에 필드가 늘어남).
- 개인정보: 세이브에는 실제 위치가 아니라 게임 안 위치만 들어간다. 클라우드 세이브(Phase 3 배포 채널)를 쓰면 별도 검토.
